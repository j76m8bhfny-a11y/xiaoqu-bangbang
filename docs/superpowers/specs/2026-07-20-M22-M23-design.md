## 一、设计决策汇总

| #   | 决策点             | 方案                                                                                                                                  |
| --- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 开发顺序           | M22 先做（4 项 filter），M23 收尾补第 5 项 + 联合查询扩展                                                                             |
| 2   | M22 subType 存储   | events 表加 `subType String?` 单列，DTO 用 `'feed'\|'walk'\|'lost'` 联合类型约束                                                      |
| 3   | M22 差异化字段     | events 表加 `petMeta Json?` 列，存 feed/walk/lost 专属字段                                                                            |
| 4   | M22 老数据迁移     | Prisma migration 内联 SQL UPDATE，老 `lost_found` 一次性转 `pet_help`+`subType=lost`+`petMeta`                                        |
| 5   | M22 API 设计       | 复用 `POST /events`，CreateEventDto 加 `subType?` + `petMeta?` 可选字段                                                               |
| 6   | M22 前端创建页     | 1 个页面 `/pages/pet-create/index?type=feed\|walk\|lost`，内部 3 套字段配置对象                                                       |
| 7   | M23 自动 completed | GroupBuyService.deliver() 用 Prisma `$transaction` 包：UPDATE item + SELECT count + 满足条件 UPDATE 主表                              |
| 8   | M22+M23 联合查询   | 新建 `GET /feed/all` 后端聚合端点，合并 events + group_buys 按 createdAt 排序分页                                                     |
| 9   | M23 名额校验       | Prisma `$transaction` + SELECT count(DISTINCT requesterId) + UNIQUE(groupBuyId, requesterId) 防重复响应                               |
| 10  | M23 reject 后行为  | reject 后该响应人不能重新响应（UNIQUE 拦截），名额释放给其他用户；被 reject 用户本期不支持重新提交（YAGNI，后续可加 PATCH item 接口） |

### 批次划分

- **批次 1（M22）**：数据库迁移 -> 后端 API+Service -> 前端创建/编辑/详情 -> filter 4 项 -> 测试 -> /review
- **批次 2（M23）**：数据库迁移 -> 后端模块 -> 前端 3 页 + filter 第 5 项 + /feed/all -> Admin 管理页 -> 测试 -> /review

## 三、M23 购物拼拼详细设计

### 3.1 数据模型

**Prisma schema 新增 2 张表**：

```prisma
model GroupBuy {
  id               String        @id @default(uuid()) @db.Uuid
  communityId      String        @map("community_id") @db.Uuid
  initiatorId      String        @map("initiator_id") @db.Uuid
  type             String        // 'seek' | 'offer'
  location         String        // 期望采购地/代购方采购地
  departAt         DateTime?     @map("depart_at")      // offer 必填
  bidCloseAt       DateTime?     @map("bid_close_at")   // offer 必填
  quota            Int           @default(5)            // offer 必填，名额
  serviceFee       String        @default("free")       // free/negotiable/具体金额
  deliveryMethod   String        @map("delivery_method") // self_pickup/door_drop/spot
  note             String?
  status           String        @default("pending_review")
  // pending_review/open/closed_for_bid/purchased/completed/closed/rejected
  aiReviewStatus   String        @default("pending") @map("ai_review_status")
  aiReviewReason   String?       @map("ai_review_reason")
  createdAt        DateTime      @default(now()) @map("created_at")
  updatedAt        DateTime      @updatedAt @map("updated_at")
  deletedAt        DateTime?     @map("deleted_at")

  community        Community     @relation(fields: [communityId], references: [id])
  initiator        User          @relation("GroupBuyInitiator", fields: [initiatorId], references: [id])
  items            GroupBuyItem[]

  @@index([communityId, type, status, createdAt])
  @@index([initiatorId])
  @@map("group_buys")
}

model GroupBuyItem {
  id           String    @id @default(uuid()) @db.Uuid
  groupBuyId   String    @map("group_buy_id") @db.Uuid
  requesterId  String    @map("requester_id") @db.Uuid
  name         String    // 商品名
  qty          Int       @default(1)
  note         String?
  status       String    @default("pending")
  // pending/confirmed/purchased/delivered/rejected
  createdAt    DateTime  @default(now()) @map("created_at")
  updatedAt    DateTime  @updatedAt @map("updated_at")

  groupBuy     GroupBuy  @relation(fields: [groupBuyId], references: [id], onDelete: Cascade)
  requester    User      @relation("GroupBuyItemRequester", fields: [requesterId], references: [id])

  @@unique([groupBuyId, requesterId]) // 防重复响应（一个响应人只能提交一次）
  @@index([groupBuyId, status])
  @@map("group_buy_items")
}
```

**新 migration** `20260720000002_add_group_buys/migration.sql`：CREATE TABLE + 索引 + UNIQUE 约束。

### 3.4 关键逻辑

**自动 completed**（deliver 方法内 `$transaction`）：

```ts
await prisma.$transaction(async (tx) => {
  await tx.groupBuyItem.update({ where: { id: itemId }, data: { status: 'delivered' } });
  const remaining = await tx.groupBuyItem.count({
    where: { groupBuyId, status: { not: 'delivered' } },
  });
  if (remaining === 0) {
    await tx.groupBuy.update({ where: { id: groupBuyId }, data: { status: 'completed' } });
    // 触发发花：主买人 1 朵 (沿用现有 ContributionService)
  }
});
```

**名额校验**（respond 方法内 `$transaction`）：

```ts
await prisma.$transaction(async (tx) => {
  const responderCount = await tx.groupBuyItem.count({
    where: { groupBuyId, status: { not: 'rejected' } },
    // UNIQUE(groupBuyId, requesterId) 保证一个响应人一行
  });
  if (responderCount >= groupBuy.quota) {
    throw new ConflictException(ErrorCodes.QUOTA_EXCEEDED);
  }
  await tx.groupBuyItem.create({ data: { groupBuyId, requesterId, ... } });
});
```

**AiReview 触发**（create/update 方法内）：

- 注入 `AiReviewService`，调用 `reviewText(note + location)`
- pass -> status='open'；reject -> status='rejected' + aiReviewReason；manual_review -> status='pending_review' 人工审核
- 沿用 `ai_content_review` 全局开关，关闭时直接 pass

### 3.5 聚合端点 `/feed/all`

**新建 `apps/api/src/modules/feed/feed.controller.ts` + `feed.service.ts` + `feed.module.ts`**：

```
GET /feed/all?page=1&pageSize=20
```

逻辑：

1. 并发 `Promise.all` 查 events（type IN [help_request, public_welfare, pet_help]，status IN [open, in_progress, processing, completed]）+ group_buys（status IN [open, closed_for_bid, purchased, completed]）
2. 两端各自按 createdAt 降序取前 N 条（pageSize \* page 偏移）
3. 合并后在内存按 createdAt 降序排序，切片返回当前页
4. 返回 `FeedItemDto[]`（统一字段：id/type/subType/title/subtitle/stats/createdAt）

> **ponytail: 简化说明** - 内存合并分页在 page>3 时性能下降。当前小区数据量小（<1000 条），YAGNI。升级路径：后续改用 Postgres UNION ALL 跨表查询。

| ----------------------------------- | --------------------------------------------------------------- |
| 老数据迁移 SQL 不可逆               | 老数据为测试数据，风险低；迁移前 dump 一份 events 表            |
| `petMeta` JSON 字段无 DB 层类型检查 | DTO 层 class-validator + Service 层手动校验分支                 |
| `/feed/all` 内存分页性能            | ponytail: 当前数据量小可接受，page>3 性能下降，后续改 UNION ALL |
| GroupBuy 名额并发竞争               | 事务内 SELECT count，高并发下可能超限；社区场景并发极低，YAGNI  |

### 4.2 明确不做的事（YAGNI）

- 不做 group_buy 金额结算（PRD §4.22 明确"纯信息同步"）
- 不做 group_buy 独立 AI 审核流程（复用 event 的 AiReviewService）
- 不做 pet_help 子分类的 Prisma enum（用 String + DTO 联合类型）
- 不做 group_buy 的 Postgres 触发器（Service 层事务处理）
- 不做 filter="我能帮忙"（PRD §4.4 已移除）

### 4.3 复用的现有基础设施

- `AiReviewService`: `apps/api/src/modules/ai-review/`（M22 直接用 event 审核，M23 注入服务）
- `EventParticipant` 表: 多帮手流程（pet_help.lost 沿用）
- `MasonryEventCard` 组件: `apps/miniapp/src/components/masonry-card/`（扩展 typeLabel）
- `BlurredList` 组件: 未认证用户的模糊预览（group_buy 列表也需要接入）
- 业主认证状态: `useAuthStore.verifyStatus`
- `FAB` 路由: 根据 filter 状态路由到对应创建页
- 通知服务: 现有 event 通知模块
- `ContributionService`: 发花逻辑（group_buy 完成时调用）
