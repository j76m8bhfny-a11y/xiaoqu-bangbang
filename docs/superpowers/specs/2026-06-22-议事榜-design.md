# 小区议事榜设计文档

**版本**: 1.0
**日期**: 2026-06-22
**状态**: 待审阅

---

## 一、背景与目标

### 1.1 现状

小程序底部 5 个 tab：首页 / 事件 / 闲置 / 好人榜 / 我的。事件包含 6 种类型（找人帮忙 / 我能帮忙 / 公益活动 / 寻宠寻物 / 公共反馈 / 讨论），公共事务类内容和个人互助混在一起，用户找不到重点，公共问题缺乏持续追踪机制。

### 1.2 目标

1. **简化入口**：合并事件和闲置为「小区广场」，底部 tab 从 5 个调整为新结构
2. **独立公共事务空间**：新增「议事榜」tab，专注小区公共事务，提供议题聚合、点赞踩、评论讨论、完结追踪闭环
3. **AI 辅助**：AI 推荐议题归并、生成事件点评、高相似度议题合并建议
4. **给物业输出改善建议**：高票议题作为物业改善参考，admin 完结后形成结案报告

### 1.3 非目标

- 不改动 admin 后台菜单结构（仅新增「议事管理」菜单）
- 不改动现有 Event 模型核心字段（仅新增关联）
- 不改动现有「好人榜」「奖章」体系
- 不做数据迁移（现有无 public_feedback/discussion 类型数据）

## 三、功能拆解

### 3.1 小程序底部 Tab 调整

**调整前**：首页 / 事件 / 闲置 / 好人榜 / 我的（5 个）
**调整后**：首页 / 小区广场 / 议事榜 / 好人榜 / 我的（5 个）

### 3.2 小区广场 Tab

**内部 3 个子 tab**：

1. **全部**：事件 + 闲置按时间混合流
2. **事件**：只显示 4 种类型 —— 找人帮忙 / 我能帮忙 / 公益活动 / 寻宠寻物
3. **闲置**：不变

**改动点**：

- 事件 tab 移除 public_feedback / discussion 类型
- 新增「全部」tab，混合流展示
- 复用现有 events / market 页面逻辑，调整 tab 结构

### 3.3 议事榜 Tab

#### 3.3.1 顶部切换

两个榜切换：**未完结榜** / **完结榜**

#### 3.3.2 议题列表（瀑布流）

- 布局：瀑布流，一屏 4-5 个卡片
- 卡片内容：
  - 议题标题
  - 状态标签（未完结 / 已完结）
  - 点赞数 / 点踩数（未完结榜）或平均星级（完结榜）
  - 事件数（如「8 个事件」）
  - 最新事件预览（标题 + 首图缩略图）
  - 完结总结预览（前 20 字 + 盖章图标，仅完结榜）

#### 3.3.3 排序规则

**未完结榜**：净赞数（点赞 - 点踩）+ 时间权重

- 公式：`score = (likeCount - dislikeCount) + timeBoost`
- `timeBoost`：发布 24 小时内 +5，48 小时内 +2，之后 +0

**完结榜**：平均星级 + 完结时间权重

- 公式：`score = avgRating * 10 + timeBoost`
- `timeBoost`：完结 24 小时内 +5，48 小时内 +2，之后 +0

**评论排序**：高赞置顶 + 时间权重

- 主评论按净赞数降序，同分按时间倒序
- 嵌套回复按时间正序（保持对话连贯）

#### 3.3.4 议题详情页

**结构**（时间线混合显示）：

1. **顶部议题信息区**
   - 议题标题
   - 状态标签
   - 点赞 / 点踩按钮 + 计数（未完结榜）或 5 星评分（完结榜）
   - 完结总结 + 盖章图标（已完结时）

2. **时间线（事件为主，评论附属）**
   - 事件卡片：标题 / 图片 / AI 点评卡片（20-30 字）/ 点赞数
   - 事件卡片下方附属评论列表（可展开折叠）
   - 评论支持嵌套（最多 2 层）+ 点赞点踩 + 带图

3. **底部操作栏**
   - 点赞 / 点踩（未完结）
   - 5 星评分（已完结）
   - 补充事件按钮（跳转发布页，预选当前议题）
   - 评论输入框

#### 3.3.5 发布公共事件

**入口**：

1. 议事榜首页右下角「+」按钮 → 发布新事件
2. 议题详情页「补充事件」按钮 → 在该议题下添加事件

**流程**：

1. 用户填写事件内容（标题 / 描述 / 图片）
2. 选择类型：公共反馈 / 讨论
3. 选择议题（AI 推荐 + 手动切换）：
   - AI 根据内容推荐 3 个最相关现有议题
   - 用户可选推荐议题、手动从列表选、或创建新议题（自己命名）
4. 提交后：
   - AI 实时生成点评（20-30 字）置于事件顶部
   - AI 实时检查议题相似度（95%+ 自动合并到老议题，通知用户）
5. 事件进入议题时间线

#### 3.3.6 互动方式

| 操作     | 对象                 | 说明                            |
| -------- | -------------------- | ------------------------------- |
| 点赞     | 议题 / 评论          | 不公开谁点的                    |
| 点踩     | 议题 / 评论          | 不公开谁点的                    |
| 评论     | 议题（附属在事件下） | 支持带图（最多 9 张）= 补充证据 |
| 回复评论 | 评论                 | 嵌套最多 2 层                   |
| 5 星评分 | 已完结议题           | 完结后评价，影响完结榜排序      |

#### 3.3.7 用户身份

- 发布事件：可匿名（复用 Event.isAnonymous）
- 评论：显示用户昵称头像
- 点赞/点踩/评分：不公开身份

### 3.4 AI 功能（四个独立开关）

**开关位置**：admin 后台「系统设置」→「AI 功能」
**环境变量**：

- `AI_TOPIC_PROVIDER=mock | openai | qwen | deepseek`（议题归并/合并）
- `AI_REVIEW_PROVIDER=mock | openai | qwen | deepseek`（内容审核，复用现有）
- `AI_COMMENT_PROVIDER=mock | openai | qwen | deepseek`（事件点评）

#### 3.4.1 议题归并（开关 1）

- **触发**：用户发布事件选择议题时
- **行为**：AI 根据事件内容推荐 3 个最相关现有议题
- **mock 实现**：关键词匹配 + 标题相似度（Jaccard）
- **真实 AI**：调 LLM 生成 embedding，余弦相似度排序取 top3

#### 3.4.2 议题合并建议（开关 2）

**两层处理**：

- **实时自动合并**：发布事件时，AI 检查所选议题与其他未完结议题相似度 ≥95%，自动合并到老议题，通知用户
- **后台扫描建议**：每天凌晨 3 点扫描，相似度 80-95% 的议题对生成「合并建议」，admin 在后台确认后合并

#### 3.4.3 事件点评（开关 3）

- **触发**：事件发布成功后实时生成
- **内容**：简短建议方案，20-30 字
- **展示**：事件详情页顶部独立卡片「AI 建议」
- **mock 实现**：从预设模板库按关键词匹配（如「花坛」→「建议联系物业绿化部门评估」）
- **真实 AI**：调 LLM 生成

#### 3.4.4 AI 内容审核（开关 4）

- **触发**：用户创建/编辑内容时（议题标题/描述、公共事件标题/描述、评论内容）
- **审核结果**：`pass`（直接发布）/ `reject`（拦截，提示"内容违规"）/ `manual_review`（进入 admin 审核队列）
- **mock 实现**：关键词匹配（黄暴词库）
- **真实 AI**：调 LLM 判断
- **关闭后**：所有内容直接 pass，不审核
- **复用现有字段**：Event.aiReviewStatus、Event.aiReviewResult；TopicComment 新增 aiReviewStatus 字段；Topic 新增 aiReviewStatus 字段

### 3.5 Admin 后台议事管理

**菜单**：新增「议事管理」（在「事件管理」下方）

#### 3.5.1 议题列表页

- 筛选：未完结 / 已完结 / 全部
- 搜索：议题标题
- 列表字段：标题 / 状态 / 事件数 / 点赞数 / 点踩数 / 平均星级（已完结）/ 创建时间
- 操作：查看详情 / 完结 / 撤销完结 / 驳回

#### 3.5.2 议题详情页

- 议题基础信息
- 事件列表（可调整归属）
- 评论列表（可隐藏违规评论）
- 完结操作：填写完结总结 → 系统自动盖章 → 进入完结榜
- 撤销完结：从完结榜移回未完结榜（保留原赞踩数据）
- 调整事件归属：移动事件到其他议题 / 合并议题

#### 3.5.3 内容审核

- 议题审核：驳回 / 隐藏违规议题
- 事件审核：驳回 / 隐藏违规事件（复用现有 Event.status）
- 评论审核：隐藏违规评论

#### 3.5.4 AI 合并建议

- 列表展示后台扫描生成的合并建议
- 操作：确认合并 / 忽略

#### 3.5.5 AI 功能开关

- 四个独立开关：议题归并 / 议题合并建议 / 事件点评 / AI 内容审核
- 关闭后对应 AI 功能不执行，节约 token

### 3.6 通知

| 场景       | 接收人               | 通知内容                              |
| ---------- | -------------------- | ------------------------------------- |
| 议题完结   | 议题下所有事件发布者 | 「XX 议题已完结：[总结前 20 字]」     |
| 评论被回复 | 被回复的评论作者     | 「XX 回复了你的评论：[内容前 20 字]」 |

**不通知**：新事件发布、议题变更、点赞点踩

## 四、数据模型

### 4.1 新增模型

#### Topic（议题）

```prisma
model Topic {
  id              String   @id @default(uuid()) @db.Uuid
  communityId     String   @map("community_id") @db.Uuid
  title           String
  description     String?
  status          String   @default("open") // open / closed
  likeCount       Int      @default(0) @map("like_count")         // 未完结榜赞数
  dislikeCount    Int      @default(0) @map("dislike_count")      // 未完结榜踩数
  closedLikeCount Int      @default(0) @map("closed_like_count")  // 完结后专用赞数
  closedDislikeCount Int   @default(0) @map("closed_dislike_count")
  ratingSum       Int      @default(0) @map("rating_sum")         // 5 星评分总和
  ratingCount     Int      @default(0) @map("rating_count")       // 评分人数
  eventCount      Int      @default(0) @map("event_count")
  commentCount    Int      @default(0) @map("comment_count")
  closedSummary   String?  @map("closed_summary")                 // 完结总结
  closedAt        DateTime? @map("closed_at")
  closedBy        String?  @map("closed_by") @db.Uuid
  createdBy       String   @map("created_by") @db.Uuid            // 创建议题的用户（手动创建或 AI 系统 ID）
  aiReviewStatus  String   @default("pending") @map("ai_review_status") // pending/pass/reject/manual_review
  aiReviewResult  Json?    @map("ai_review_result")
  createdAt       DateTime @default(now()) @map("created_at")
  updatedAt       DateTime @updatedAt @map("updated_at")

  // relations
  events          Event[]
  comments        TopicComment[]
  likes           TopicLike[]
  ratings         TopicRating[]
  mergeSuggestions TopicMergeSuggestion[]

  @@index([communityId, status, likeCount])
  @@map("topics")
}
```

#### TopicComment（议题评论）

```prisma
model TopicComment {
  id             String   @id @default(uuid()) @db.Uuid
  topicId        String   @map("topic_id") @db.Uuid
  eventId        String?  @map("event_id") @db.Uuid   // 附属在哪个事件下，null=直接评论议题
  userId         String   @map("user_id") @db.Uuid
  parentId       String?  @map("parent_id") @db.Uuid  // 嵌套回复，最多 2 层
  content        String
  images         Json     @default("[]")              // 补充证据图片
  likeCount      Int      @default(0) @map("like_count")
  dislikeCount   Int      @default(0) @map("dislike_count")
  replyCount     Int      @default(0) @map("reply_count")
  aiReviewStatus String   @default("pending") @map("ai_review_status")
  status         String   @default("visible")         // visible/hidden/deleted
  createdAt      DateTime @default(now()) @map("created_at")
  updatedAt      DateTime @updatedAt @map("updated_at")

  topic          Topic    @relation(fields: [topicId], references: [id])
  event          Event?   @relation(fields: [eventId], references: [id])
  user           User     @relation(fields: [userId], references: [id])
  parent         TopicComment?  @relation("CommentReplies", fields: [parentId], references: [id])
  replies        TopicComment[] @relation("CommentReplies")
  likes          TopicCommentLike[]

  @@index([topicId, eventId, likeCount])
  @@map("topic_comments")
}
```

#### TopicLike（议题赞踩）

```prisma
model TopicLike {
  id        String   @id @default(uuid()) @db.Uuid
  topicId   String   @map("topic_id") @db.Uuid

  user      User     @relation(fields: [userId], references: [id])

  @@unique([topicId, userId, scope])
  @@map("topic_likes")
}
```

#### TopicMergeSuggestion（议题合并建议）

```prisma
model TopicMergeSuggestion {
  id           String   @id @default(uuid()) @db.Uuid
  communityId  String   @map("community_id") @db.Uuid
  sourceTopicId String  @map("source_topic_id") @db.Uuid  // 被合并的议题
  targetTopicId String  @map("target_topic_id") @db.Uuid  // 合并到的议题
  similarity   Float                                    // 相似度 0-1
  status       String   @default("pending")              // pending / approved / rejected
  createdAt    DateTime @default(now()) @map("created_at")
  resolvedAt   DateTime? @map("resolved_at")
  resolvedBy   String?  @map("resolved_by") @db.Uuid

  targetTopic  Topic    @relation("MergeTarget", fields: [targetTopicId], references: [id])

  @@index([communityId, status])
  @@map("topic_merge_suggestions")
}
```

### 4.2 修改现有模型

#### Event 模型新增字段

```prisma
model Event {
  // ...现有字段...
```

## 六、AI 实现细节

### 6.1 Provider 抽象

```typescript
// apps/api/src/modules/ai/topic-provider.interface.ts
export interface TopicProvider {
  // 推荐议题（发布事件时）
  suggestTopics(
    content: { title: string; description: string },
    candidates: Topic[],
  ): Promise<TopicSuggestion[]>;
  // 检查相似度（实时合并 + 后台扫描）
  computeSimilarity(topicA: Topic, topicB: Topic): Promise<number>;
  // 生成事件点评
  generateEventComment(event: {
    title: string;
    description: string;
    type: string;
  }): Promise<string>;
}
```

### 6.2 Mock Provider

- `suggestTopics`：Jaccard 相似度（标题分词 + 描述关键词）
- `computeSimilarity`：Jaccard 相似度
- `generateEventComment`：关键词模板匹配

### 6.3 真实 AI Provider

- `suggestTopics`：embedding + 余弦相似度
- `computeSimilarity`：embedding + 余弦相似度
- `generateEventComment`：LLM 调用，prompt 限制 20-30 字

### 6.4 后台任务

- 每天凌晨 3 点扫描议题相似度，生成合并建议
- 使用 `@nestjs/schedule` 的 Cron 任务

## 十一、审查发现的额外问题及处理

### 11.1 议事类事件状态机简化

现有 Event.status 有 7 种状态。议事类事件（public_feedback/discussion）只用 3 种：

- `pending_review`（待审核）→ `open`（已发布，挂到议题）→ `rejected`（驳回）
- 不使用 `in_progress / processing / completed / closed`
- 议题完结不影响事件状态，事件保持 `open`

### 11.2 议题标题来源

- **用户手动创建**：用户命名
- **AI 自动创建**（用户发布事件选"创建新议题"）：
  - mock：直接用事件标题
  - 真实 AI：LLM 从事件标题提取关键词生成简短议题标题
- admin 可编辑议题标题

### 11.3 FeedbackProcessLog 废弃

现有 `FeedbackProcessLog` 模型（给 public_feedback 事件用的处理日志）废弃：

- 保留现有数据，不再新增
- 处理进度通过议题的完结总结 + 评论区记录

### 11.4 议题 communityId 必填

- 议题必须属于一个小区
- 不支持跨小区议题
- 议题列表只查当前小区

### 11.5 议题标题唯一性

- 同一小区内议题标题不强制唯一（避免 AI 生成时冲突）
- 通过 AI 相似度合并机制去重
- admin 手动合并时可选择保留哪个标题

### 11.6 AI 审核 fail-open 策略

- AI 审核服务不可用（网络错误、超时）时：内容直接发布（fail-open），不阻塞用户
- admin 后台可看到 AI 审核异常日志
- 避免 AI 故障导致用户无法发布内容
