## 4. MCP 工具使用指南（关键）

### ⚠️ 4.1 模型限制（必须知道）

**当前 API**：火山引擎方舟 `https://ark.cn-beijing.volces.com/api/coding`
**当前模型**：`glm-5.2`（**纯文本，不支持图片输入**）

**直接影响**：

- ❌ 不能用 `mp_screenshot`（weapp-dev-mcp）
- ❌ 不能用 `browser_take_screenshot`（Playwright）
- ❌ 不能用 `take_screenshot`（Maestro）
- 任何截图类工具调用都会返回 `400 "Model only support text input"`

**替代方案（全部用文本工具）**：

- Playwright：用 `browser_snapshot`（accessibility tree 文本）代替 `browser_take_screenshot`，用 `browser_evaluate` 拿 DOM 文本
- weapp-dev-mcp：用 `page_getElement` / `page_getElements` / `element_getWxml` / `element_getStyles` / `mp_getLogs` 代替 `mp_screenshot`
- Maestro：本身基于文本选择器（YAML `id:` / `text:`），输出纯文本日志，无需截图

### 4.2 weapp-dev-mcp（小程序自动化）

**用途**：操作小程序页面、元素、调用页面方法、查日志
**已安装**：全局 npm 包 `@yfme/weapp-dev-mcp` + Claude Code user scope 配置
**WebSocket 端点**：`ws://localhost:9420`

**典型流程**：

```
1. mp_ensureConnection（必须先调用，失败则见 §4.3 排错）
2. mp_currentPage（拿当前页路径）
3. page_getElements（按 selector 找元素）
4. element_tap / element_input（交互）
5. page_getData（拿页面 state）
6. mp_getLogs（看 console 日志）
```

**M22/M23 常用 selector**：

- 邻里帮 filter 第 4/5 项：找 `[data-testid="filter-pet-help"]` 或文字"宠物帮帮" / "购物拼拼"
- FAB 按钮：找 `.home__fab` 或 `button[aria-label="create"]`（具体见元素 wxml）
- 表单字段：先 `page_getElements` 列出所有 input，再用 `element_input`
- 列表卡片：`.masonry-card` 或 `[data-event-id]`

### 4.3 weapp-dev-mcp 已知坑（来自项目 memory）

**坑 1：`simulatorPluginLibVersion`**

- 如果 `apps/miniapp/project.config.json` 里 `simulatorPluginLibVersion` 是 `{}` 对象（不是字符串），会报 `t.charAt is not a function`
- **已修复**：当前值已设为 `""`（空字符串），不要改回 `{}`

**坑 2：连接失败重试**

- 首选 `mp_ensureConnection` 连接
- 失败 -> 不要盲重试，用 `mp_listProjects` 或带 `reconnect=true` 重连一次
- 还失败 -> 检查微信开发者工具是否打开 + 是否开启了服务端口 9420

**坑 3：Taro 版本兼容**

- 项目用 Taro 4，某些 `page_callMethod` 在 Taro 4 上行为与 Taro 3 不同
- 如果 `page_callMethod` 报错，改用 `element_callMethod`（通过元素实例调用）

**总 45 检查点，8 小节**：

| #   | 小节                       | 检查点数 | 关键 ID 范围    |

| 1   | 创建求代购 (seek)          | 6        | GB-001 ~ GB-006 |
| 2   | 创建代购方 (offer)         | 6        | GB-007 ~ GB-012 |
| 3   | 列表展示与 filter          | 5        | GB-013 ~ GB-017 |
| 4   | 详情页与响应               | 6        | GB-018 ~ GB-023 |
| 5   | 主买人确认/拒绝响应        | 5        | GB-024 ~ GB-028 |
| 6   | 状态机流转                 | 6        | GB-029 ~ GB-034 |
| 7   | 名额限制 + 自动完成 + 激励 | 6        | GB-035 ~ GB-040 |
| 8   | Admin 管理                 | 5        | GB-041 ~ GB-045 |

### M23 测试重点

1. **seek vs offer 字段差异**（GB-001~012）
   - seek：必填商品清单（≥1 项），不填 quota（默认 999）
   - offer：必填 quota + departAt + bidCloseAt，不填商品清单

2. **状态机流转**（GB-029~034，关键）

   ```
   pending_review -> open -> closed_for_bid -> purchased -> completed
                       -> rejected                                  -> closed (手动关闭)
   ```

   - closed_for_bid：截止接单后不可再响应
   - purchased：标记已购回
   - 自动 completed：全部 item delivered 后事务内自动转（无需手动调用 complete）
   - closed：手动关闭（终止流程）

3. **名额限制**（GB-035~037）
   - 按"响应人"计名额（一人占一名额，不论带几件商品）
   - offer 满名额后响应 -> 409 QUOTA_EXCEEDED
   - seek 不限名额（quota=999）
   - 拒绝响应后名额释放，可继续接受新响应

4. **激励**（GB-038~040）
   - 自动 completed 时给主买人发 1 朵花
   - 响应人不发花（只发布信息撮合，不是劳动）

5. **Admin 下架**（GB-044，关键）
   - 下架违规拼单 -> `status=closed`（**注意：不是 cancelled**）
   - GroupBuyStatus 枚举无 `cancelled` 值
   - 已 closed/rejected 状态不展示"下架"按钮

## 12. 应急方案

### weapp-dev-mcp 连不上

1. 检查微信开发者工具是否打开
2. 检查设置 -> 安全设置 -> 服务端口是否开启（端口 9420）
3. 检查项目目录是否是 `apps/miniapp`（不是项目根目录）
4. 重启微信开发者工具
5. 仍失败 -> 降级为人工测试，记录到 findings.md

### 后端报错 500

1. 看后端日志（终端 1）
2. 检查数据库连接（端口 5433 是否对了）
3. 跑 `pnpm db:migrate` 确认 schema 最新
4. 跑 `pnpm --filter @xiaoqu-bangbang/api test` 确认单测通过

### Admin 页面白屏

1. 看 Admin 终端日志
2. 检查 `.env.local` 的 `NEXT_PUBLIC_API_URL=http://localhost:3000/api/v1`
3. 确认后端已起

### GroupBuyStatus 报错

- 如果任何接口返回包含 `cancelled` 字样的错误，说明某处仍用了 `cancelled` 枚举（应为 `closed`）
- 定位：`grep -r "'cancelled'" apps/api/src/modules/group-buys/ apps/api/src/modules/admin/`
- 修复：改为 `closed`
